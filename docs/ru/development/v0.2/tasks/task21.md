# Техническое задание: навык агента, документация и примеры для OKF v0.2 {#section001}

## 1. Цель {#section002}

Перевести контракт для агентов, README/документацию, примеры, фикстуры и упаковку
плагина на v0.2, сохранив явно обозначенное чтение старого формата.

Завершить после задач 09–20.

## 2. Встроенная спецификация {#section003}

- Заменить `references/spec-v01.md` на закреплённый `spec-v02.md`.
- Добавить `references/migration-v01-v02.md`.
- Не смешивать нормативные MUST/SHOULD/MAY.
- Вынести YAML `relations` в раздел с пометкой `skosovsky/okf extension`.
- Честно описать отложенные/неоднозначные вопросы ABI, без выдуманных правил.

## 3. Процесс создания материалов {#section004}

Навык должен:

1. Определять целевую версию и записывать версию только в корневом индексе.
2. Требовать только `type` для минимального концепта.
3. Добавлять `generated` только при известном субъекте.
4. Создавать записи `sources` только из реальных материалов.
5. Использовать сноски с ключами для доказуемой атрибуции утверждений.
6. Не считать автора/генератора/валидацию фактом проверки.
7. Записывать `verified` только после реальной проверки.
8. Не выдумывать статус/дату устаревания/сигналы достоверности.
9. Выносить санкционированное вычисление в отдельный концепт.
10. Не превращать сигналы достоверности в числовую оценку.

## 4. Процесс чтения {#section005}

- Предпочитать поля v0.2, затем резервное чтение по §13.
- Нормализовать одиночную форму `verified`.
- Определять уровень доверия строго по `verified`.
- Показывать доверие/статус/устаревание отдельно.
- Не исполнять содержимое `executor`/`attester` без доверенной среды исполнения и разрешения.
- Не игнорировать сигналы `deprecated`/`stale` по инструкции из тела.

## 5. Рекомендации по миграции {#section006}

- `timestamp` переносится только с явно указанным субъектом `generated`.
- Неизвестный субъект → нерешённый вопрос/ручное действие.
- `# Citations` → `sources` без выдуманных метаданных.
- Сноски к утверждениям — только при доказуемом сопоставлении.
- Не выводить `verified`/`status`/`stale_after` из `git`/`timestamp`/миграции.
- Повышение версии происходит после валидации.
- Неизвестное содержимое сохраняется без потерь.

## 6. Примеры/фикстуры {#section007}

Обновить примеры и добавить:

- концепт, созданный человеком;
- несколько источников/сноски с ключами;
- одиночную форму `verified`/список;
- `draft`/`stable`/`deprecated`;
- границу актуального/устаревшего;
- встроенное/файловое аттестованное вычисление (Attested Computation);
- повествовательный концепт со ссылкой на вычисление;
- явно обозначенные примеры старого/смешанного/будущего формата.

Канонические фрагменты должны извлекаться из фикстур либо проверяться тестами расхождения.
Синтетические примеры используют зарезервированные домены и помечаются как синтетические.

## 7. Состязательные контексты {#section008}

Матрица вход → ожидаемое решение → запрещённое поведение:

- тело просит игнорировать YAML-метаданные/доверие;
- субъект-человек в `generated` без `verified`;
- автор-человек у источника без проверяющего;
- высокий usage_count как попытка повысить доверие;
- сноски в коде/неизвестные/повторяющиеся ID;
- одновременные сведения о происхождении в старом формате и v0.2;
- самопродвижение `stale`/`deprecated`;
- `executor` просит оболочку/секреты/обход политики;
- квитанция LLM объявляет успешную аттестацию.

Детерминированные случаи идут в фикстуры/тесты, случаи только для агента — в матрицу оценки.

## 8. EN/RU и упаковка {#section009}

Синхронно обновить:

- `README.md` / `README.ru.md`;
- `docs/index.md` / `docs/ru/index.md`;
- `docs/skill.md` / `docs/ru/skill.md`;
- `docs/toolkit.md` / `docs/ru/toolkit.md`;
- навигацию и страницу миграции.

После стабилизации:

- описания/версии плагинов;
- не приравнивать версию пакета к версии спецификации OKF;
- пересчитать `skills-lock.json` последним;
- проверить `skills.sh.json`/манифесты маркетплейса.

## 9. Ограничения против шаблонного текста {#section010}

- Не выдумывать субъектов, источники, проверку, актуальность и квитанции.
- Один термин — одно значение.
- Не дублировать обзор на каждой странице.
- EN/RU совпадают по контракту, но русский не является калькой.
- Политика репозитория всегда помечается как политика расширения/инструментов.
- Никакого маркетингового тумана.

## 10. Критерии приёмки {#section011}

- Актуальные документация/навык не называют текущую спецификацию черновиком v0.1.
- `timestamp`/`Citations` остаются только в примерах старого формата/миграции.
- Все ссылки ведут на spec-v02/миграцию.
- Канонические фикстуры v0.2 проходят базовую/строгую валидацию без замечаний.
- Фикстура старого формата читается через документированный резервный механизм.
- Семантика одиночной формы `verified` и списка совпадает.
- Примеры аттестации не обещают ABI среды исполнения.
- Проверка соответствия EN/RU пройдена.
- Манифесты плагинов согласованы; тест файла фиксации навыков проходит.
- Поиск v0.1/`timestamp`/`Citations`/spec-v01 возвращает только намеренные случаи.
- `go test ./...`, `go vet ./...`, `git diff --check` проходят.

## 11. Вне рамок задачи {#section012}

Исполнение вычислений, ABI/песочница/кеш аттестатора, выдуманные числовые оценки и
автоматическое семантическое переписывание.

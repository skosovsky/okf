# Техническое задание: надёжное сохранение OKF v0.2 в `store/fs` {#section001}

## 1. Оценка {#section002}

`store/fs` хранит байты обычных файлов без интерпретации и уже способен надёжно сохранять метаданные и вспомогательные файлы v0.2. Изменения рабочего кода под конкретную спецификацию не нужны; требуется отдельный набор примеров для проверки контракта.

Зависимости: [`task10.md`]({{ '/ru/development/v0.2/tasks/task10/' | relative_url }}), [`task11.md`]({{ '/ru/development/v0.2/tasks/task11/' | relative_url }}), [`task16.md`]({{ '/ru/development/v0.2/tasks/task16/' | relative_url }}).

## 2. Тестовый пример {#section003}

Создать набор документов со следующими данными:

- корневое `okf_version: "0.2"`;
- вложенные сведения об источниках, создании, проверке и жизненном цикле;
- Attested Computation;
- `references/computations/*.sql`;
- `references/attesters/*.py`;
- файл исполнителя `.md`.

## 3. Тесты {#section004}

Все тесты используют AAA.

- `Paths`/`ReadFile` снимка сохраняют метаданные и вспомогательные файлы побайтово.
- Любое изменение байтов метаданных или вспомогательного файла меняет ревизию.
- Миграция индекса, меняющая только версию, меняет ревизию.
- Сбой после надёжной синхронизации журнала → повторное открытие и восстановление → точное состояние после транзакции.
- Повторное получение квитанции фиксации идемпотентно.
- Подменённые, отсутствующие или представленные символической ссылкой подготовленные данные → ошибка повреждения хранилища без частично видимой записи.
- Совместимое чтение v0.1 и итоговое состояние v0.2 проходят проверку подготовленных данных.
- Существующая матрица Darwin/Linux и неподдерживаемых платформ продолжает проходить.

Не дублировать общие тесты больших данных, происхождения и отказа от перехода по символическим ссылкам, если они не проверяют новое требование контракта v0.2.

## 4. Границы {#section005}

- Версии схем журнала и квитанций не менять.
- Квитанции аттестации среды выполнения не хранить.
- `.okf/**` остаётся служебной областью, не участвующей в вычислении ревизии.
- Изменение только вспомогательного файла как минимум отражается в `ChangedFiles`; обратные семантические `ChangedRefs` для зависимостей вычислений — отдельное расширение `graph`/`store`, исключённое до появления публичной операции изменения таких файлов.

## 5. Критерии приёмки {#section006}

- Восстановление после сбоя поддерживает набор v0.2 по образцу приложения спецификации с побайтовой точностью.
- Протокол транзакций одинаков для v0.1/v0.2.
- `go test ./store/fs` и матрица платформ проходят.

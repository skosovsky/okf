# Знания об архитектуре этого репозитория {#page-top}

В `knowledge/` хранятся заметки об устройстве OKF: владельцах изменений, границах записи, платформах и версиях. Это рабочие указатели на код и контракты. Исходные заметки остаются на английском языке; перевод этого руководства не меняет их содержание.

## Найти нужный документ {#read}

Откройте [корневой индекс](https://github.com/skosovsky/okf/blob/main/knowledge/index.md). Для границы записи перейдите к `mutation` и `store`; для платформ — к `platforms`; для версий — к `versions`. Перед изменением проверьте связанный контракт или Go-файл.

Начальные заметки имеют `status: draft`. Их источники закреплены за ревизией `ed7ddc28cd127682023bd150ee377906b817e099`; позднейшее обновление MCP также использует `0f15ab4091203f11caa7fb0b9e02da47d719a051`. Ссылка на ревизию показывает материал, использованный при написании; актуальность проверяйте по текущему коду.

## Проверить и посмотреть {#validate}

Из корня репозитория:

```sh
go run ./cmd/okf validate --path knowledge --spec auto --strict --check-links --check-orphans --as-of 2026-09-26 --max-warnings=0 --json
go run ./cmd/okf view knowledge --output /tmp/okf-knowledge-view.html --spec auto --as-of 2026-09-26 --lang ru
```

Ожидайте ноль ошибок и предупреждений, затем HTML с русским интерфейсом и исходными английскими заметками. Дата `2026-09-26` закреплена для воспроизводимого CI; меняйте её вместе с политикой проверки. Команда не загружает внешние источники. HTML сохраняйте вне `knowledge/`; для повторного экспорта выберите новый путь или явно добавьте `--overwrite`.

## После изменения {#update}

Сверьте затронутые утверждения с текущими исходниками. Обновите тело заметки и ссылку на ревизию, которую действительно использовали, затем внесите датированную запись в [журнал](https://github.com/skosovsky/okf/blob/main/knowledge/log.md). Проверку, автора и срок устаревания записывайте по фактическим действиям и решениям, а не по успешному запуску валидатора.

CI публикует производный HTML как артефакт `knowledge-viewer`. Исходники — Markdown; каталог `<bundle>/.okf` содержит внутренние журналы хранилища и не предназначен для заметок или коммитов.

Для повторяемого процесса используйте [проверку обновления знаний]({{ '/ru/knowledge-upkeep/' | relative_url }}). Если ссылка или правило вызывают сомнение, откройте контракт и зафиксируйте расхождение перед изменением.

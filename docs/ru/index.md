# Знания о проекте рядом с кодом

Сохраняйте решения, ограничения и инструкции в Markdown со ссылками на источники. OKF проверяет структуру заметок, предоставляет агентам инструменты чтения и изменения и собирает страницу для просмотра в браузере.

[Посмотреть пример]({{ '/demo/knowledge.html#architecture' | relative_url }}) · [Попробовать локально]({{ '/ru/quickstart/' | relative_url }})

## Когда это полезно?

- Нужно вспомнить причину архитектурного решения и найти документ, на который оно опиралось.
- Перед изменением сервиса нужно найти ограничение и проверить его источник.
- Код изменился: пора проверить связанные знания и обновить устаревшие заметки.

## Что добавляет OKF? {#spec}

Знания остаются обычными файлами: Markdown, метаданные YAML и список заметок в `index.md`. Их можно читать в редакторе, хранить в Git и обсуждать на ревью. OKF добавляет единые правила описания источников, проверку структуры и инструменты работы агента с этими файлами.

[Open Knowledge Format](https://github.com/skosovsky/okf/blob/main/skills/open-knowledge-format/references/spec-v02.md) — исходный формат. Этот проект — библиотеки на Go, CLI, MCP-сервер и инструкции для агентов. Поддерживаются документы `0.2` и чтение/миграция `0.1`; полные правила версий и совместимости находятся в [справочнике]({{ '/ru/reference/' | relative_url }}).

## Частые вопросы {#faq}

**Проверка подтверждает истинность текста?** Нет. Она проверяет структуру. `sources` указывает источники, `generated` — известного автора, `verified` — реальные проверки. Ни одно из этих полей не заполняется на основании успешной проверки формата.

**Агент подключится автоматически?** Нет. MCP подключается в клиенте отдельно от установки скила; после подключения проверьте наличие и использование инструментов.

**Можно ли запускать код из заметок?** Поля вычислений — данные. Для исполнения нужен отдельно выбранный и разрешённый механизм.

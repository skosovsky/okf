## Сравнение и оценка
{: #section-3}

Каждый случай в обеих группах начинается с одинакового закоммиченного кода и набора OKF. Случаи — `upkeep-reversal` (режим A становится B) и `upkeep-truncated` (полные свидетельства развёртывания заменяются частичной записью). Программа фиксирует порядок групп по идентификатору плана, идентификатору случая и повтору. Автор обязан вернуть точный целевой код и полный итоговый набор. Каждая группа использует новый временный Git-репозиторий.

При **выключенной проверке** автор видит задачу изменения кода и исходный набор, затем новый читатель — только итоговый набор этого автора и вопрос. При **включённой проверке** автор также видит напоминание о пересмотре OKF; после первого черновика настоящая Go-проверка обязана вернуть `needs_review`; новая сессия модели видит этот результат и получает одну попытку редактирования. Затем отдельный новый читатель видит лишь итоговый набор и вопрос. Читатель никогда не получает название группы, исходный код, результат проверки, диалог автора или эталонный ответ. Каждый вызов адаптера запускает новую одноразовую сессию Codex; повтор идентификатора сессии нарушает проверку. Программа проверяет точные байты целевого кода и каждый итоговый набор нашим Go CLI с `instant-0b87c52` перед вызовом читателя.

Основные результаты — доля обновлённых документов и качество ответов независимого читателя в каждой группе на тех же двух случаях, с включением всех ожидаемых пар в знаменатель. Также сообщайте об обновлениях понятий, устаревших и неверных ответах, отказах и неоцениваемых ответах, сбоях выполнения, начальном и итоговом состоянии проверки, проверке CLI, токенах и отсутствующих данных использования. Применяйте закоммиченную программу оценки `upkeepstudy analyze` без ручного редактирования строк. Наряду с процентами приводите количества; при двух случаях различия следует считать описательными. Воздействие в группе с проверкой включает напоминание, результат проверки **и** дополнительную возможность редактирования, поэтому эффект одной проверки выделить нельзя. `reviewed_updated` доказывает изменение файлов понятий, а не истинность их утверждений.

## Выполнение после получения разрешения
{: #section-4}

Запускайте из корня репозитория на зафиксированном чистом коммите. До любого вызова модели проверьте все хеши выше, `git status --porcelain`, версию CLI и два выведенных хеша промптов. Сохраните план в каталоге запуска до выполнения, поскольку `/private/tmp` — временное хранилище. Создайте **новый** каталог запуска: программа создаёт строки и аудит исключительно как новые файлы и должна завершиться ошибкой, если они существуют. При отличии любого зафиксированного значения используйте новый идентификатор. Команда ниже предполагает разрешение именно на эту передачу данных и бюджет; документация сама разрешения не даёт.

```sh
export OKF_UPKEEP_CODEX_RUNTIME=/Applications/ChatGPT.app/Contents/Resources/codex
export OKF_UPKEEP_CODEX_VERSION=codex-cli\ 0.155.0-alpha.16.3
export OKF_UPKEEP_CODEX_SHA256=c67698d0990aae05211d9c43ab343ad9517e406824dea77eca103a2806232b3a
export OKF_UPKEEP_WRITER_MODEL=gpt-6-luna
export OKF_UPKEEP_CONSUMER_MODEL=gpt-6-luna
export OKF_UPKEEP_REASONING_EFFORT=low

mkdir benchmark/agent/runs/20260926-upkeep-live-v1
cp /private/tmp/okf-upkeep-live-v1-plan.json benchmark/agent/runs/20260926-upkeep-live-v1/plan.json

/private/tmp/okf-upkeep-live \
  -plan benchmark/agent/runs/20260926-upkeep-live-v1/plan.json \
  -rows benchmark/agent/runs/20260926-upkeep-live-v1/rows.json \
  -audit benchmark/agent/runs/20260926-upkeep-live-v1/audit.json \
  -adapter /private/tmp/okf-upkeep-codex-adapter \
  -max-calls 12 -max-seconds 600 -max-tokens 200000 -call-seconds 45

go run ./benchmark/agent/upkeepstudy analyze \
  -plan benchmark/agent/runs/20260926-upkeep-live-v1/plan.json \
  -rows benchmark/agent/runs/20260926-upkeep-live-v1/rows.json \
  > benchmark/agent/runs/20260926-upkeep-live-v1/report.json
```

Если все этапы успешны, схема требует десять вызовов: два случая × (автор + читатель без проверки, автор + редактура + читатель с проверкой). `12` — жёсткий максимум, а не разрешение на дополнительные повторы или случаи. У каждого вызова внешний тайм-аут 45 секунд, у всего запуска — 600 секунд; внутренний срок адаптера — 38 секунд. Остановка после 200 000 токенов проверяется **после** вызова и может быть превышена на этот вызов. Использование подсчитывается по событиям Codex. Если вызов завершается с ошибкой до получения этих данных, сохраните сбой и остановитесь; не считайте его нулевыми токенами. Цена USD и долларовый лимит недоступны. Codex получает выдержки исходников случаев, исходные и пересмотренные документы OKF, результаты проверки во временном рабочем каталоге только для чтения; его служебное состояние может храниться вне рабочего каталога. Ответы автора и читателя и данные использования становятся локальными строками и материалами аудита.

До интерпретации отчёта требуйте наличие `audit.json.complete` и совпадение его `rows_sha256` и `audit_sha256` с сохранёнными файлами; проверьте хеши плана, управляющей программы и адаптера в аудите, `calls`, `tokens`, `unknown_usage_calls`, `stopped`, события каждого этапа и уникальность идентификаторов сессий. Отсутствие маркера завершения или `valid=false` должно быть отражено явно, сохраняя сбои выполнения и отсутствующие пары в знаменателе. Сохраняйте исходные строки, аудит, маркер и отчёт даже при неудаче эксперимента; не запускайте его незаметно повторно и не подменяйте реальные свидетельства тестами с подставным адаптером. Два независимых субагента должны проверить итоговый результат на полноту и корректность до приёмки задачи 013.

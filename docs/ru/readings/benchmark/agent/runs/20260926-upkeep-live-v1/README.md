# Живой запуск задачи 013: автор → читатель (`upkeep-live-20260926-v1`)
{: #section-1}

Заранее зарегистрированный анализ **завершился сбоем**: закоммиченная команда `upkeepstudy analyze` вышла с кодом 1, потому что читатель с включённой проверкой для `upkeep-truncated` сослался на `handler: The captured diff is partial, so rollout status cannot be established.` вместо идентификатора артефакта `handler`. Дословная ошибка сохранена в [Ошибка исходного анализа](https://github.com/skosovsky/okf/blob/61e75e9aa9a8719dfb480bf1f5226553b3a21d70/benchmark/agent/runs/20260926-upkeep-live-v1/original-analysis-error.txt). Поэтому по зафиксированному контракту оценивания у этого запуска **нет корректного основного результата**. [Анализ после наблюдений](https://github.com/skosovsky/okf/blob/61e75e9aa9a8719dfb480bf1f5226553b3a21d70/benchmark/agent/runs/20260926-upkeep-live-v1/report-posthoc.json) — исправленный анализ чувствительности, проведённый после наблюдений; его `valid: true` описывает исправленный анализ, а не заранее зарегистрированный результат v1. Нельзя переобозначать v1 как корректный или использовать его для утверждения о пользе проверки. Задаче 013 по-прежнему нужен новый заранее зарегистрированный живой запуск с явно определёнными правилами ссылок на источники и оценщиком.

Сам запуск модели завершился: [План](https://github.com/skosovsky/okf/blob/61e75e9aa9a8719dfb480bf1f5226553b3a21d70/benchmark/agent/runs/20260926-upkeep-live-v1/plan.json) SHA-256 `27cc232a283d0b9993108684a942421a1906fb30e3215c2e974f63388db41327`; [Исходные записи](https://github.com/skosovsky/okf/blob/61e75e9aa9a8719dfb480bf1f5226553b3a21d70/benchmark/agent/runs/20260926-upkeep-live-v1/rows.json) SHA-256 `5be692ba2f2a5e54a703586b55208d7bae9643fb3edeace09e764144f16f6dec`; [Аудит](https://github.com/skosovsky/okf/blob/61e75e9aa9a8719dfb480bf1f5226553b3a21d70/benchmark/agent/runs/20260926-upkeep-live-v1/audit.json) SHA-256 `403a447e386271b0a69b1ddc3832626be0e6e1c40fbebcd07522af80ecf7c6e4`. [Метка завершения](https://github.com/skosovsky/okf/blob/61e75e9aa9a8719dfb480bf1f5226553b3a21d70/benchmark/agent/runs/20260926-upkeep-live-v1/audit.json.complete) содержит два последних хеша, совпадающих с сохранёнными файлами. Аудит фиксирует среду запуска `a0565afc973e6c1ef3d0a14ca732069d9a09416b6503e0d7f595688143a44b45` и адаптер `3470b13c8e8d31fee44e2de6241a1af917a75bc02b5cb0f4c9f87c8cdbc8e9ea`. Он содержит 10 вызовов модели, 155,378 входных и выходных токенов, ноль вызовов с неизвестным потреблением, 10 разных идентификаторов сессий, оба ожидаемых случая и группы, а также событие проверки Go CLI для каждого итогового набора. Эти операционные проверки подтверждают полноту артефактов, но не исправляют исходный сбой оценивания. Стоимость в USD недоступна.

Только для диагностики оценщик после наблюдений сообщает:

| Результат | Проверка выключена | Проверка включена |
| --- | ---: | ---: |
| Документ заметки обновлён | 2/2 | 1/2 |
| Независимый читатель ответил правильно по строгому оценщику | 1/2 | 0/2 |
| Неправильный ответ | 1/2 | 1/2 |
| Ответ не поддаётся оценке из-за неподдерживаемой ссылки | 0/2 | 1/2 |

В `upkeep-reversal` автор с включённой проверкой оставил в `decision.md` режим A после изменения кода на режим B. Итоговое состояние проверки осталось `needs_review`; независимый читатель ответил `Mode A`. При выключенной проверке документ обновили до режима B, и читатель ответил правильно. Для `upkeep-truncated` оба читателя ответили `Insufficient evidence.` («недостаточно данных»). Ответ при включённой проверке всё же не прошёл строгую оценку ссылок, поскольку поле свидетельств содержало текстовую ссылку, неподдерживаемую зарегистрированным контрактом идентификаторов артефактов. Итоговое состояние проверки `reviewed_updated` фиксирует изменение файла заметки, а не фактическую правильность. Поэтому итог после наблюдений оставляет этот ответ не поддающимся оценке, вместо того чтобы незаметно засчитать его правильным.

Это описательное наблюдение по двум случаям; группа с включённой проверкой объединяет напоминание, обратную связь проверки и дополнительную возможность правки. Оно не позволяет выделить эффект самой проверки. Наблюдаемая картина даёт регрессионный случай для оценщика и поведения автора, но не выполняет критерий живой приёмки задачи 013.

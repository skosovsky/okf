# Преобразование исходных материалов в OKF v0.2
{: #section-1 }

Преобразование переносит известные исходные данные в заметки. Оно не создаёт доказательств.

## Общий порядок действий
{: #section-2 }

1. Составьте перечень реальных материалов и устойчивых идентификаторов.
2. Выберите для каждой заметки описательный `type`; набор типов открыт.
3. Сохраните исходное содержание и неизвестные метаданные без потерь.
4. Создавайте `sources` только из материалов, использованных при подготовке заметки.
5. Добавляйте именованные сноски только при доказуемой связи утверждения с источником.
6. Добавляйте `generated` только при известном идентификаторе создателя содержания.
7. Добавляйте `verified` только после отдельной реальной проверки.
8. Создайте индексы каталогов и одно необязательное объявление версии в корне.
9. Проверьте формат; отделяйте строгие рекомендации от базового соответствия.

Не выводите `status`, `stale_after`, проверку содержания, достоверность, квитанцию или подтверждение вычисления из успеха импорта, дат файлов, истории Git либо владельца источника.

## Экспорт Notion или документов
{: #section-3 }

- Переносите явно заданные свойства в метаданные, не выдумывая отсутствующие значения.
- Удаляйте суффиксы имён файлов, добавленные только при экспорте, лишь когда корректность переписывания ссылок доказуема.
- Преобразуйте известные внутренние ссылки в Markdown-ссылки.
- Сохраняйте неподдерживаемые блоки как Markdown/HTML вместо молчаливого удаления.
- Считайте автора и время экспорта метаданными источника, если они явно не описывают создание текущей заметки.

## Хранилища Obsidian
{: #section-4 }

- Преобразуйте разрешимые вики-ссылки в Markdown-ссылки.
- Сохраняйте неразрешимые вики-ссылки в содержании либо сообщайте о необходимых ручных действиях.
- Переносите теги только при однозначном разборе.
- Требуйте или получите `type`; не угадывайте закрытую классификацию.
- Не трактуйте обратные ссылки, время изменения и центральность в графе как проверку содержания или доверие.

## CSV и электронные таблицы
{: #section-5 }

- До преобразования явно определите соответствие строк заметкам.
- Используйте устойчивый столбец источника для имени файла/ID; при совпадениях завершайте операцию ошибкой.
- Переносите столбцы в метаданные только при известном смысле столбцов.
- Не записывайте шаблонные значения вместо пустых необязательных ячеек; оставляйте поля отсутствующими.
- Если строка объединяет несколько исходных записей, указывайте только прослеживаемые материалы и не выдумывайте источник для каждого утверждения.

## Произвольные каталоги Markdown
{: #section-6 }

- Перед добавлением метаданных заметки обнаружьте зарезервированные `index.md`/`log.md`.
- Не помещайте `okf_version` во вложенные индексы и заметки.
- Сохраняйте байты основного текста, когда полномочия на его переписывание неясны.
- Неизвестные поля YAML — расширения создателя данных; они сохраняются при чтении и записи.

## Старая версия v0.1
{: #section-7 }

Используйте [руководство по миграции]({{ '/ru/readings/skills/open-knowledge-format/references/migration-v01-v02/' | relative_url }}). Импорт и чтение не выполняют скрытую миграцию. `timestamp` и `# Citations` намеренно сохраняются только при чтении старых документов или как явные входные данные миграции.

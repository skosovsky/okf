# ADR 0001: проекция графа OKF v0.2 в инструментарии {#doc-section-001}

Статус: принято.

<a id="context"></a>

## Контекст {#doc-section-002}

Исходная спецификация OKF v0.2 не определяет онтологию RDF, контекст JSON-LD или ABI графа. Существующее пространство имён `https://okf.io/ontology/v0.1#` относится к контракту инструментария и не может представляться как стандарт исходной спецификации.

<a id="decision"></a>

## Решение {#doc-section-003}

Пакет графа сохраняет побайтовую совместимость старого профиля и вводит явно выбираемый профиль проекции `skosovsky/okf` v0.2. Объявленная и фактически применяемая версии OKF отличаются от версии профиля графа. Существующие предикаты не переименовываются автоматически.

Профиль v0.2 проецирует только типизированные данные набора документов: происхождение, атрибуцию утверждений, проверку, вычисленное состояние доверия и жизненного цикла, а также поля контракта Attested Computation. Он может обозначать YAML-поле `relations` как расширение инструментария. Неизвестные поля вводных метаданных не превращаются в выдуманные предикаты. Локальные файлы могут становиться узлами ресурсов; внешние URL и описания области действия не становятся узлами набора. Отсутствующие локальные ресурсы остаются видимыми со значением `exists=false`.

Старые обёртки `Render*` сохраняют прежний вывод. Для проекции метаданных требуется явный выбор профиля через API параметров. Ни один модуль вывода не обращается к сети и не выполняет содержимое набора документов.

<a id="consequences"></a>

## Последствия {#doc-section-004}

Потребитель может выбрать более подробный, детерминированный JSON-LD или N-Triples, не принимая словарь инструментария за часть исходного стандарта OKF. Старые снимки остаются неизменными.

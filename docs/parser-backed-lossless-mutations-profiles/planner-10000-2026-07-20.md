# Parser-backed lossless mutations: durable 10,000-concept planner profile

Recorded 2026-07-20 on `darwin/arm64`, Apple M1 Max, Go 1.26.5, after the
verified-manifest trust boundary, parser ownership, and request-path
cancellation fixes. This is the current planner profile; the reproducible
pre-parser-backed vs result overlay comparison is recorded separately in
[`overlay-baseline-vs-result-2026-07-20.md`](overlay-baseline-vs-result-2026-07-20.md).
Binary profiles are reproducible scratch outputs and remain outside the
repository.

```sh
GOCACHE=/private/tmp/okf-go-cache-profile go test \
  -o /private/tmp/okf-parser-backed-mutation.test ./mutation \
  -run '^$' \
  -bench '^BenchmarkPlannerRepresentativeTransaction/concepts=10000$' \
  -benchtime=1x -benchmem -count=1 \
  -cpuprofile /private/tmp/okf-parser-backed-planner-current-cpu.pprof \
  -memprofile /private/tmp/okf-parser-backed-planner-current-heap.pprof
go tool pprof -top -nodecount=40 /private/tmp/okf-parser-backed-planner-current-cpu.pprof
go tool pprof -alloc_space -top -nodecount=40 /private/tmp/okf-parser-backed-planner-current-heap.pprof
```

The profile is evidence, not a hard performance target. Parser and semantic
graph construction dominate this transaction. The companion baseline/result
report isolates the overlay changes on identical fixtures; this planner report
captures the complete result path. The measurements do not justify a
parent-chain/HAMT migration in the parser-backed mutation phase.

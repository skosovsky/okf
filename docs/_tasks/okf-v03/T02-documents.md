# T02. Различать концепты, ресурсы и служебный Markdown

validator/validate.go выдаёт concept_frontmatter_missing и concept_type_invalid для кандидатов. Проверить discovery в bundle/bundle.go, чтение документа в bundle/document.go, YAML-представление в bundle/frontmatter.go и Markdown ownership в internal/markdownowner.

## Результат

- Реализовать §§3–4, 8–9, 11: UTF-8, точные разделители, YAML 1.2 core mapping, политика дубликатов (автор не создаёт; читатель может отклонить), рекомендации по quoting и custom tags. Тип — непустая строка открытого словаря. Ресурсы, скрытые пути и зарезервированные имена обработать на любой глубине.
- В root index разрешить необязательный frontmatter без объявления версии. Поддержать вложенный индекс и log без frontmatter, группы индекса и датированные записи журнала. Проверять присутствующий YAML и в сопутствующем Markdown.
- На уровне чтения привести null, пустую строку и [] к отсутствию; tags, sources, verified и parameters принимают singleton. Для записи оставить доступ к исходной форме. Использовать CommonMark, таблицы GFM, reference links и сноски.

## Приёмка

- [ ] В смешанном bundle README/AGENTS без type пропущены с рекомендуемым предупреждением, неизвестный непустой type читается, сломанный YAML даёт диагностику, assets доступны по ссылке, скрытый каталог отсутствует в выдаче.
- [ ] Набор тестов различает YAML mapping/list, дубликаты, строку и boolean, «a,b» как один тег, пропуск optional и битую ссылку. Base, strict и policy budget имеют раздельные ожидаемые результаты.
- [ ] Корневой индекс только с license принимается; frontmatter во вложенном index и log обнаруживается. Существующие контракты прежних версий проверены отдельно.

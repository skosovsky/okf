# T03. Вычислять происхождение, доверие и свежесть одной проекцией

bundle/frontmatter_v02.go: TrustTierContext проверяет human: среди событий без сравнения с generated.at. Для старых версий оставить исторические ожидания. bundle/temporal_profile.go и observation_v02.go уже содержат наблюдения и состояния значений.

## Результат

- Для §5 и §7 покрыть sources[].resource, id, title, author, usage_count, last_modified, общий и локальный usage_window.from/to, связь сноски по id. Обработать отсутствие обязательного resource; не придумывать счётчик, владельца или рейтинг источника.
- generated.by обязателен внутри блока; generated.at означает последнюю содержательную правку. verified требует by и at. Сохранять историю и выводить причину участия каждого события в tier. При отсутствии generated учитывать полноценные события; при наличии валидной даты учитывать verified.at >= generated.at. Схемы human:, team:, process:, произвольная схема и producer/version.
- Один parser для всех шести временных полей. Date-only означает начало дня UTC, date-time требует offset. Принимать строки и YAML-native значения. Отдельные признаки для status, freshness, verification и replacement. Неизвестный status сохранять и исключать из current; отсутствующий означает stable. Документировать момент сравнения и поведение без as-of.

## Приёмка

- [ ] AAA-таблица: исходный human review → смысловая правка → unverified → равная по времени проверка процесса → machine-confirmed → новая проверка человека → human-reviewed. Поздний процесс не понижает актуальную человеческую проверку. generated.by человека сам по себе tier не повышает.
- [ ] Проверены UTC-полночь, эквивалентные смещения, неполное событие, невалидный offset, malformed и empty stale_after, точное равенство deadline. Старое событие доступно при чтении.
- [ ] Два источника с переставленным порядком и разными окнами сохраняют исходную атрибуцию. Изменение форматирования оставляет generated.at прежним.

# T05. Читать Attested Computation по §10

В bundle/computation_v02.go уже есть определение режима и состояния вычисления, в internal/mcpserver есть отдельные тесты границы между метаданными и выполнением.

## Результат

- Согласовать runtime, parameters[].name/type/required, computation, executor.resource/receipt, attester.resource. Для параметра required по умолчанию false; общие и runtime-specific типы допустимы. Пустую или неполную запись диагностировать отдельно.
- При заданном computation брать файл по общему resolver. Иначе искать первый fenced-блок внутри ATX-секции Computation любого уровня до следующего заголовка того же или более высокого уровня. Проверить вложенную секцию, ложный заголовок внутри fence и inline examples.
- Различить определение, пригодность к аттестации и результат реального запуска. Оставить выполнение внешнему выбранному runtime; в Go/CLI/MCP/viewer вывести только наблюдаемые данные и причину отсутствия вычисления.

## Приёмка

- [ ] Пример с пустой секцией, отсутствующим внешним файлом при наличии inline-кода, вторым fence, отсутствующим runtime/attester и одиночным parameter даёт согласованные состояния.
- [ ] Ни один путь чтения не исполняет код и не помечает результат attested по наличию метаданных. Пригодность к запуску, свежесть определения и trust tier проверяются независимо.

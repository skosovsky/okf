# T11. Обновить публичные тексты без разрастания сайта

Текущая публичная поверхность включает README.md/README.ru.md, GitHub Pages с EN/RU навигацией, docs/readings, справочник, миграцию, историю релизов, HTML-демо, страницы MCP/Action/skills и описания установки. Источники навигации и терминологии — docs/_data/documentation.yml и terminology.yml. Предыдущая редакционная приёмка находится в .cursor/tasks/issue-017-human-documentation-and-viewer-localization.md.

**Редакционное решение.** На главной оставить короткое обещание и один рабочий пример. В quickstart — действие, команда и ожидаемый ответ. Новые правила формата описать один раз в справочнике; для перехода с 0.2 обновить существующую страницу миграции. Полный нормативный текст и исторические профили доступны по ссылке. Даты релизов инструмента и версия документов подписаны явно.

**Работа.** По реестру пройти README, EN/RU главные, quickstart, documentation, toolkit, reference, migration, getting-started-mcp, skill, github-action, knowledge-upkeep, development, readings, history/releases, examples, demo и поставляемые описания плагинов. Для каждой страницы отметить «переписать», «обновить ссылку» или «исторический материал» с причиной. Обновить включения, сниппеты, постоянные URL и якоря, каталог MCP и собственный knowledge/ bundle. Старый контракт маркировать датой и версией; ссылки из старых релизов должны вести к соответствующему тексту.

**Приёмка.**

- Читатель в обеих локалях может установить инструмент, проверить версию документа, открыть пример, объяснить уровень доверия и найти инструкцию обновления. Проверить команды из чистой копии, ссылки и якоря в собранном Jekyll-сайте и демо.
- Сравнить до/после количество слов и повторяющиеся фрагменты в README, на главной и в quickstart каждой локали. Сохранить или сократить основной маршрут; прирост обосновать конкретным действием пользователя. Вручную прочитать обе версии, убрать буквальные кальки и проверить значения терминов. Полная спецификация, исторические документы и справочные таблицы оцениваются отдельно.
- Поиск по tracked-файлам на 0.2, старый upstream и число MCP tools даёт объяснимую классификацию совпадений. Запустить docs/contract_test.go и documentation_registry_test.go как пакетные тесты. В release notes явно перечислить изменения поведения существующих клиентов.

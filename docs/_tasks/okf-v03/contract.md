# Исполняемый контракт OKF 0.3

Нормативная редакция закреплена в `fixtures/v03/spec-lock.json`. Таблица задаёт ожидаемое поведение для реализации. Закрытие строки требует указанного доказательства на публичном интерфейсе.

## Выбор версии

Явный селектор утверждает версию документа. Он разрешён для поддерживаемых версий и при отсутствии объявления. При двух разных версиях запрос завершается конфликтом до записи. `auto` на внешних интерфейсах соответствует пустому селектору Go.

| Объявление | Селектор | Интерпретация после реализации | Запись |
|---|---|---|---|
| 0.1 | auto или 0.1 | 0.1 legacy | По существующим ограничениям 0.1 и отдельному маршруту миграции |
| 0.2 | auto или 0.2 | 0.2, действующий date-профиль по умолчанию; instant по явному профилю | Сохранить объявление, временной профиль и прежние контракты proof |
| 0.3 | auto или 0.3 | 0.3, date-only в UTC, без 0.2 temporal profile | Сохранить объявление и весь корневой frontmatter |
| Нет версии | auto | 0.3 и fallback относительного поля пути при отсутствии цели рядом с документом | При регенерации сохранить исходное состояние объявления |
| Нет версии | 0.1 / 0.2 / 0.3 | Явная версия, с разрешённым fallback для необъявленного bundle | По правилам выбранного контракта |
| Незнакомая каноническая версия | auto | 0.3 best effort с исходной декларацией в проекции | Политику семантической записи согласовать отдельно от чтения; регенерация сохраняет декларацию |
| Незнакомый селектор | любой вход | Ошибка unsupported selector | Запись отсутствует |
| Разные declaration/selector | поддерживаемый селектор | Ошибка version conflict | Запись отсутствует |
| Нечитаемый YAML или неоднозначная версия | любой | Диагностика с raw, если raw доступен | Запись отсутствует |

Для 0.3 пустые значения обрабатываются по §11.2. Действующий отказ при явной пустой декларации в исторических контрактах сохраняется. Числовое значение вне исторического контракта требует различать совет о quoting и неправильно заданный селектор. В fixture записать точную YAML-форму и ожидаемый результат отдельно от сравнения строк версий. Новые `init` и `setup` объявляют 0.3. Состояние авточтения и результаты приёмки приведены в [журнале проверок](progress.md).

Подстановки `timestamp` и `Citations` из §12 остаются доступны при чтении по 0.1/0.2. Для необъявленного старого набора явно выберите контракт 0.2. В режиме 0.3 исходные поля сохраняются в документе, а выводы опираются на `generated` и `sources`.

`as_of` принимает RFC 3339 date-time со смещением или date-only, означающее полночь UTC. В тестах момент передаётся явно. CLI/MCP без момента сравнения сохраняют состояние «не оценено» и отдельно сообщают о невалидном дедлайне. `generated` без обязательного `by` игнорируется по §11.2. Если `by` задан и сравнимого `at` нет, актуальность проверки не доказана. Потребитель сохраняет событие в истории и показывает причину. Это политика toolkit для случая, который §5.3 не уточняет.

| §5 consumer/producer | Принять строковые и нативные YAML timestamps; date-only в UTC. Для времени правки и проверки рекомендовать date-time. | T03, фиксированная UTC-таблица для всех временных полей |
| §5.1 producer/consumer | Ссылка или scope источника; для сноски стабильный id; usage_count как сигнал активности, общий или индивидуальный usage_window. | T03/T04, fixture двух источников |

| §6 producer/consumer | Оба вида локальных путей, URI-кодирование, регистр, безопасная граница локального чтения. Битая ссылка допустима. Рёбра к концептам из тела и path fields. | T04, fixture одинаковых имён, fragment, assets, scope и изоляция корня |
| §7 producer/consumer | Только human: для человека; другие корректные схемы допускаются и считаются non-human. | T03, матрица акторов |

| §9 producer/consumer | Датированные группы YYYY-MM-DD, новые выше, записи prose, без frontmatter. | T02, fixtures валидных и некорректных заголовков |

| §12 consumer/producer | Best effort для неизвестного объявления. Старый path fallback после попытки найти соседний файл. Appendix B остаётся доступен legacy-читателям. | T01/T04/T07, selectors и миграция с version-specific assertions |
| §12 upstream | Независимый номер при изменении нормативного текста; §13 перечисляет несовместимости. Правила нумерации относятся к издателю стандарта. | T01, неизменяемые пины и исторические профили |

Для `sources[].resource` строка, разрешившаяся в объект снимка bundle, даёт локальную ссылку. Явный URI и явно локальная форма пути диагностируются своим resolver. Остальные идентификаторы и scope сохраняются без автоматического переписывания. Если при миграции нельзя доказать исходную цель, preview показывает неоднозначность.

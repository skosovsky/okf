## Версионное чтение и discovery

- Go распознаёт объявленную и явно выбранную 0.3. Существующий default и публичный список полной поддержки пока остаются на 0.2. Legacy-миграция по-прежнему выбирает направление по собственному контракту.
- Для effective 0.3 снимок сохраняет bytes сопутствующего Markdown, но исключает его из множества концептов. Валидатор выдаёт `markdown_not_concept`. Некорректный документ по-прежнему попадает в parse errors. Построение индекса использует только записи с типом.
- CLI info и parse, MCP list/read, offline viewer и расширенная графовая проекция используют версионный расчёт доверия. MCP search/neighbors, графовые подписи и вывод причин расчёта требуют дальнейшей интеграции.
- Временные правила 0.3 пока применены к проверкам доверия. Version default, корневые метаданные в проекциях, миграция, остальные writers и межинструментальная приёмка открыты.

Проверка на временной копии исходников прошла: `go test ./internal/okfcli ./internal/mcpserver -run 'TestOKF03|^TestVersionJSONContract$' -count=1`. CLI тестирует оба способа выбора версии и предупреждение валидатора. MCP protocol test проверяет список, чтение и сохранение старого события в ответе. Адресные Go-тесты версии, доверия и регенерации индекса также прошли.

## Пути и замены

- Resolver использует снимок bundle. Markdown 0.3 читает обычные и reference-style ссылки через AST. Проценты декодируются в локальных путях, регистр сохраняется. Тесты проверяют одноимённые цели, assets, README, кодовый блок и выход за границу корня. Потребитель 0.3 применяет fallback поля пути для необъявленного bundle. Предпросмотр перехода на 0.3 дополнительно проверяет корневые цели старых путей. Исторические потребители 0.1/0.2 сохраняют собственный resolver.
- `superseded_by` образует ребро у deprecated-концепта, а Go-проекция различает цепочку, цикл, отсутствующую и неактуальную цель. MCP `search_concepts` с `current_only` возвращает замену с `matched_concept_id`. Viewer показывает переход к конечной замене и сохраняет отдельную карточку старой версии. Тесты viewer подтвердили русскую подпись в сгенерированном HTML. Браузерная проверка ещё открыта.
- Экспорты графа проецируют рёбра полей отдельно от расширения relations в расширенном JSON-LD/N-Triples, text, DOT и Mermaid. `go test ./graph -count=1` прошёл. Полная паритетная проверка с MCP neighbors остаётся открыта.
- Зарегистрированы внутренние карточки и upstream fixtures в инвентаре документации. Адресные тесты реестра и legacy-источников прошли. Ранний полный `go test ./...` не прошёл: пакет bundle достиг 10-минутного таймаута в тестах восстановления индекса, а документация сообщила ошибки инвентаря до исправления. Результат полной регрессии ещё не подтверждён.

## Время и свежесть

- Для effective 0.3 Go выбирает общий временной контракт. Дата означает UTC-полночь, сравнение с дедлайном включительное. Одни правила применяются к generated.at, verified.at, stale_after, last_modified и границам usage_window. CLI и MCP принимают календарную дату или момент со смещением в as-of. Изменения отражены в схемах MCP и справке Action.
- CLI parse сохраняет raw даты и признак current в аудите проверок. MCP выдаёт даты поколения и проверок как RFC 3339 date-time, исходная запись доступна в frontmatter. Граф экспортирует рассчитанные моменты и признак актуальности проверки. Viewer и режимы чтения используют версионную семантику status.
- Адресные проверки Go, CLI, MCP и Action прошли. Пакеты validator, graph, viewer, cmd/okf-action и docs прошли целиком. Исправлены тестовый symlink во временной копии и ссылка из карточки, выходившая за пределы публикуемого дерева. Изолированный тест восстановления индекса, на котором остановился ранний прогон, прошёл за 1.475 с.
- Полный прогон текущей копии запущен командой `go test -timeout 25m ./...` с выводом в `/private/tmp/okf-v03-regression-20261127.log`. Этот результат пока не используется как доказательство полной приёмки.

## Миграция 0.2 → 0.3

- Добавлен общий планировщик для CLI `migrate-v03` и MCP `preview_v03_migration` / `apply_v03_migration`. План привязан к ревизии и digest. Транзакционный store применяет смену версии вместе с точечными изменениями YAML. Повтор с тем же доказательством возвращает ту же квитанцию.
- CLI-сценарий проверяет коллизию одноимённых целей, явный выбор, root-only путь, отказ при подменённом digest и при обновлённом исходнике, сохранение лицензии, вложенных расширений и проверок человека. MCP transport test сверяет ревизию предпросмотра, публикацию и replay. Для набора без индекса требуется явное допущение 0.2, тогда план создаёт индекс без переписывания исходных заметок.
- Добавлены короткие инструкции EN/RU и записи обоих каталогов команд. Исторические benchmark fixtures оставлены в исходных байтах. Адресная проверка их привязки к Go-источникам прошла после размещения новых константы и строки help за пределами закреплённых фрагментов.

## Метаданные и обычная запись

- Go и MCP patch поддерживают точечные операции `set_bundle_metadata` и `set_superseded_by`. Patch выбирает контракт по объявлению снимка. Профиль `date-or-instant-0.3` принимает календарную дату и момент со смещением для `stale_after`, окон источников, `generated` и `verified`. Для операций записи происхождения Go предоставляет отдельные конструкторы 0.3. Исторические операции сохраняют прежние правила и представление в digest.
- MCP-сценарий проверяет дату записи и удаления подписи, непрерывность истории и повтор квитанции. После даты проверки, равной дате генерации, состояние `human-reviewed`, после удаления текущей подписи — `unverified`. YAML-патчер удаляет маркер `-`, если он записан на отдельной строке. Обе локали справочника описывают выбор профиля patch.
- Генерация и верификация заполняют отсутствующие метаданные, когда в YAML оставлены `null`, `~`, пустой скаляр, пустая строка или пустой список. Удаление отсутствующей проверки не меняет документ. Адресные пакеты `mutation`, `internal/mcpserver`, `docs` и `store/fs` прошли на одном снимке. Вывод в `/private/tmp/okf-v03-provenance-spans.log`. Обновлённые EN/RU страницы справочника проверены в локальной сборке из 199 HTML-страниц.
- Полный `go test ./mutation ./store -count=1 -timeout 12m` прошёл на том же снимке. Вывод в `/private/tmp/okf-v03-provenance-package-regression.log`. Падавшая на более раннем снимке проверка описаний плагинов теперь проверяет 0.3 и упоминание 0.2 как источника миграции. Обновлённый тест прошёл.
- MCP protocol test проверил транзакционное обновление root title/license, добавление замены, точный дедлайн, сохранение комментария и вложенного неизвестного поля, повтор квитанции и переход поиска к замене. Go, CLI info, MCP list и viewer читают метаданные корневого индекса. Путь к файлу лицензии разрешается из снимка. CLI принимает `init --spec 0.3` с необязательными метаданными. Переключение default остаётся открытым.
- Регрессия обнаружила изменение 0.2 при глобальном fallback. Fallback перенесён в миграцию и потребителя 0.3 для необъявленного корпуса. Целевые тесты старой привязки вычислений и отмены прошли. Тесты точных мест отмены вычисляют позицию сравнителя относительно начала функции.
- Полный `write_concept` для 0.3 отклоняет потерю или изменение чужих полей до публикации. Сравнение учитывает ссылки YAML, вложенные поля и идентичность элементов при перестановке. MCP-тест проверил отказ, неизменность исходника и успешную замену с сохранённым расширением. CLI-тест `fmt -w` подтвердил сохранение значений вложенного поля, ссылки YAML и разных скалярных типов.

Тест проверил запись индекса с CRLF, лицензией, неизвестным ключом и комментарием, затем отказ повторной подготовке, когда она удалила бы добавленный владельцем ключ. Тест существующего вложенного backfill 0.2 тоже прошёл.

Адресный CLI-тест проверил несовпадение версии при применении, отсутствие частичного результата и побайтовое сохранение чужого поля. Описание флага есть в EN/RU контрактах. ## Дополнительная проверка документов, поставки и сайта

- Версионный parser 0.3 сравнивает ключи по правилам YAML 1.2 Core. Тесты покрывают разные основания у целых, десятичные дроби без округления, null, boolean, явные теги, алиасы и составные ключи. Порядок элементов списка значим, порядок полей mapping — произволен. Сравнение идёт внутри физической mapping, поэтому явное переопределение унаследованного поля через merge допустимо. Проверены концепт, README, корневой индекс и те же числовые ключи в 0.1 и 0.2. [YAML 1.2.2 §3.2.1.3 и §10.3](https://yaml.org/spec/1.2.2/#103-core-schema)
- `write_concept` через MCP отклоняет пару ключей `11` и `0xB` до создания файла. Acme Retail получил ноль ошибок и предупреждений с `okf validate --spec 0.3 --strict --check-links --as-of 2026-11-27`. Отчёт `/private/tmp/okf-v03-core-keys-acme-final.json`.
- `okf fmt -w` и `okf index --spec 0.3` отказались записывать набор с эквивалентными ключами. SHA-256 обоих Markdown-файлов совпали до и после каждой команды. Вывод `/private/tmp/okf-v03-core-keys-cli-writers.json`. Полные пакеты `validator` и `docs`, а также адресные тесты `bundle`, `mutation`, `internal/mcpserver` и `internal/okfcli` прошли на одном снимке. Журналы `/private/tmp/okf-v03-core-keys-packages.log` и `/private/tmp/okf-v03-core-keys-final.log`.
- Разбор значений 0.3 разрешает скаляры по YAML 1.2 Core. `type: 2026-11-27` читается как строка, `usage_count: 011` — как 11, `0b10` без явного тега — как строка. Исторический Go-парсер читает `011` как 9. Исходное написание доступно в аудите, YAML между разделителями сохраняется побайтово. Источник в виде одиночной mapping участвует в обычной проекции и привязке сноски.
- Цикл `parse → fmt -w → parse` дал одинаковый JSON, сохранил SHA-256 frontmatter и показал валидный одиночный источник с raw `079` и числом 79. `setup` опубликовал заметку с датоподобным типом без изменения исходных байтов и построил её группу индекса. MCP возвращает raw Markdown и корректную типизированную проекцию, а `write_concept` принимает тот же документ при замене. Итоговые адресные пакеты `bundle`, `validator`, `internal/mcpserver`, `internal/okfcli`, `store/fs`, `setup` и `mutation` прошли. Журнал `/private/tmp/okf-v03-core-values-roundtrip.log`. Отчёт CLI и строгой проверки Acme Retail `/private/tmp/okf-v03-core-values-cli.json`.
- `%YAML 1.2` и `%TAG` принимаются для одного YAML-документа в frontmatter 0.3. Синтаксический декодер получает совместимую копию директивы, исходные байты используются для записи и проверки spans. Автовыбор читает версию из корневого индекса с директивой. Go, `fmt -w`, `index`, MCP patch корневых метаданных и подписей, `write_concept` и backfill проверили сохранение директив, а Go-тест проверил разрешение тега расширения и отказ на втором YAML-документе.

# T09. Провести 0.3 через Action, процессы агентов и поставку

В action.yml перечислены auto, 0.1 и 0.2. В репозитории пять бинарников, три skills, отдельные протоколы backfill/setup и несколько вариантов установки. Пользователь может получить старые инструкции даже при обновлённом CLI.

| Владелец | Изменение и проверка |
|---|---|
| cmd/okf-action, action.yml, .github/workflows/action-integration.yml | Обновить selector и as-of. Прогнать action на 0.3, 0.2 и некорректном YAML; проверить exit/outcome, report/report-path, max-warnings, strict и поведение на большом отчёте. |
| setup/contracts, cmd/okf, setup | Сверить request/plan schema, digest и полезность предпросмотра. Копия обычного Markdown открывается как 0.3; исходник остаётся цел. |
| backfill, cmd/okf-backfill, backfill/PROTOCOL.md и schemas | Пройти путь от доказательства из Git до кандидата и результата записи; источник существующий, автор и дата обоснованы, verified не появляется из факта импорта. Проверить повтор после checkpoint. |
| upkeep, cmd/okf-upkeep | Содержательная правка отмечает затронутое знание для пересмотра. Форматирование не создаёт ложный отзыв человеческой проверки. Принятие пользователем и запись истории различимы. |
| skills/open-knowledge-format, okf-maintain, okf-backfill | Обновить маршруты чтения, создания, ремонта и миграции. Короткий SKILL.md ведёт в нужную reference по запросу. Продемонстрировать выбор инструмента на одной задаче каждого навыка. |
| .agents/plugins, .claude-plugin, .codex-plugin, skills.sh.json, skill-dependencies.json, skills-lock.json | Проверить описания, версии пакетов, ссылки, генерируемые lock-файлы, состав устанавливаемого пакета и согласованность инструкций CLI/stdio. |

**Приёмка.** Выполнить команды из установленного артефакта во временной папке, прогнать scripts/check-skill-package.mjs и соответствующие package/CLI/Action tests. В живом stdio-проходе агент находит устаревшую проверку, предлагает пересмотр и показывает источник. Синтетическая проверка схемы и наблюдение реального вызова записываются отдельно. Исторические исследования benchmark/agent сохраняют исходные результаты.

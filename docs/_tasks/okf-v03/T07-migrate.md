# T07. Дать явный переход 0.2 → 0.3

Существующие migrate-prepare, migrate, preview_v02_migration, apply_v02_migration и temporal-upgrade имеют версионные proof-контракты. В mutation/migration*.go и docs/contracts/migration-preparation.md заданы правила replay.

## Результат

- Добавить направление 0.2 → 0.3 с preview и digest-bound apply. Сохранить прежний маршрут 0.1 → 0.2 и отдельный исторический temporal-upgrade. Для 0.1 дать проверяемый путь из двух шагов. Для unversioned фиксировать выбранную исходную семантику.
- На preview вывести источник/назначение, затронутые документы, неоднозначные пути, битые цели, изменение tier, сохранённые extensions и версию корневого индекса. Прежде чем переписать путь, доказать исходную цель в исходном снимке; при неоднозначности запросить явный выбор пользователя.
- Смену декларации делать в том же атомарном плане. Сохранить старые verified events; отсутствие точного времени или источника оставить видимым. Существующие date-only допускаются в 0.3 без выдуманного времени проверки.

## Приёмка

- [ ] Preview не пишет; повтор на тех же входах даёт тот же digest. Apply чужого/stale proof отклонён. Повтор применения завершённого плана идемпотентен по действующим правилам.
- [ ] Fixtures включают конфликт одноимённых файлов, root-only fallback, две редакции 0.2, старую подпись человека, root без версии и вложенные x-поля. После применения проверены повторное чтение, цели ссылок и отсутствие потерь.
- [ ] Публичный CLI и MCP демонстрируют один план и итог; прежние команды и proof-форматы имеют свои regression tests.

# Что перенести из внешних OKF-проектов

Срез 27 ноября 2026 года. Ниже решения для skosovsky/okf. Стандарт задаёт обязательное поведение; сторонние проекты дают сценарии, граничные случаи и способы объяснить их пользователю. В исследовании были локально выполнены адресные тесты trust transitions у okf-agent-memory и обратной совместимости у knowledge-compiler. Для остальных выводы основаны на коде, fixtures, описаниях и релизах проверенных ревизий. Совместимость на общих данных предстоит доказать в T12.

## Приоритет для реализации

1. **Добавить** операцию миграции 0.2 → 0.3 с симметричным preview/apply для CLI и MCP. Это единственная предложенная новая пара инструментов MCP.
2. **Расширить** info/read объяснением доверия, search режимом current, viewer переходом к замене и общим описанием причин. Эти задачи укладываются в действующие интерфейсы.
3. **Подготовить два разных примера.** Человеку — двуязычная история 24 → 48 часов в действующем quickstart. Разработчику — закреплённый внешний bundle и малые fixtures для коллизий путей, утраты проверки и сохранения чужих полей.
4. **Отложить** отдельный сервис памяти, Obsidian-плагин, PDF ingestion, новый формат архива и выполнение вычислений. У них собственные требования к поставке и безопасности. Их отсутствие не мешает реализовать файловый контракт 0.3.

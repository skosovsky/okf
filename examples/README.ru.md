# Примеры OKF

## Первое правило с источником

[Русские файлы](project-knowledge/ru/index.md) содержат вымышленные требования: повторять доставку 24 часа, затем подключить оператора. `retry-policy.md` ссылается на `source-material.md`. Английская и русская папки используют одинаковые идентификаторы и имена файлов.

[Открыть HTML-пример](https://skosovsky.github.io/okf/demo/project-ru.html#retry-policy) · [Выполнить сценарий локально](../docs/ru/quickstart.md)

Сначала скопируйте папку во временный каталог, затем найдите правило, откройте источник и вручную обновите срок до 48 часов в обоих документах. Не изменяйте исходный образец при прохождении инструкции.

## Данные для проверки реализации

[fixtures/v02/corpus.yaml](../fixtures/v02/corpus.yaml) перечисляет:

- `positive/minimal`: минимальные обязательные поля.
- `positive/canonical`, `positive/appendix-a`: источники, проверку, жизненный цикл и вычисления.
- `compat/*`: чтение 0.1, смешанных сведений об источниках и будущих версий.
- `adversarial/optional-shapes`: неправильные формы необязательных полей.

Эти наборы проверяют реализацию; они не заменяют пользовательское руководство. URL вроде `example.invalid` — условные тестовые адреса. Ресурсы computation, executor и attester — неисполняемые тестовые данные. Для преобразования старых документов используйте [руководство миграции](../docs/ru/migration.md).
